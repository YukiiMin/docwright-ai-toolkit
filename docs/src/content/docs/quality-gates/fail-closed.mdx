---
title: Structured Diagnostics & Error Handling
description: How to inspect ResultEnvelope diagnostics in Python, MCP, and CLI workflows.
---

Docwright never fails silently. Every operation returns a structured `ResultEnvelope` containing `success` (`bool`), `result` (`dict`), and `diagnostics` (`errors`, `warnings`, `info`).

## Inspecting Diagnostics in Python

```python
from doctools.operations.xlsx import xlsx_validate

res = xlsx_validate(file_ref="output/financial_report.xlsx")
print("Execution success:", res.success)

for err in res.diagnostics.errors:
    print(f"[ERROR {err.code}] {err.message} (Location: {err.location})")

for warn in res.diagnostics.warnings:
    print(f"[WARN  {warn.code}] {warn.message} (Location: {warn.location})")
```

## Inspecting Diagnostics in CLI / CI Pipelines

When running via the `docwright` CLI, the process exit code automatically reflects the diagnostic severity:
- **Exit Code `0`**: `success=True` and zero warnings/errors.
- **Exit Code `1`**: `success=True` with non-blocking warnings.
- **Exit Code `2`**: `success=False` or one or more validation errors detected.
- **Exit Code `64`**: CLI usage or JSON syntax error.
