When AI agents attempt to generate or modify enterprise office documents by generating code using raw Python libraries (`python-docx`, `openpyxl`, or `xlsxwriter`), silent corruptions occur.

Here are the 4 fundamental structural failure modes that occur in practice:

---

## 1. The ECMA-376 Last Paragraph Rule (`ERR_DOCX_001`)

Under the **ECMA-376 Standard for Office Open XML (§17.4)**, every table cell (`<w:tc>`) MUST terminate with at least one paragraph (`<w:p>`). 

When an AI writes:
```python
# BROKEN AI CODE:
cell = row.cells[0]
cell.text = ""  # If empty, python-docx can omit the closing <w:p> tag
```

The resulting XML violates the schema:
```xml
<!-- INVALID OPENXML: Triggers Word Repair Warning -->
<w:tc>
  <w:tcPr><w:tcW w:w="4500" w:type="dxa"/></w:tcPr>
  <!-- Missing <w:p> here! -->
</w:tc>
```

When opened in Microsoft Word, the user sees:
> *"Word found unreadable content in 'report.docx'. Do you want to recover the contents of this document?"*

**Docwright's Guarantee**: The `docx.build_document` engine automatically enforces canonical ordering and injects `<w:p/>` in every empty cell.

## 2. Multi-Page Table Splitting (`ERR_DOCX_003`)

In business reports, tables often span 2 to 10 pages. Without strict XML attributes, Microsoft Word splits table rows mid-sentence across page breaks, and readers lose column context.

```
Without cantSplit & tblHeader:
Page 1: [ Header A | Header B ]
        [ Row 1: Some long text ]
        [ Row 2: Part 1 of tex- (SPLIT ACROSS PAGE!) ----------------- ]

Page 2: [ -t continuing here ]  <-- No header! Reader is lost!
        [ Row 3: Next data ]
```

```
With Docwright Guaranteed Invariants:
Page 1: [ Header A | Header B ]
        [ Row 1: Some long text ]
        [ Row 2: Moved cleanly to page 2 via <w:cantSplit/> ]

Page 2: [ Header A | Header B ]  <-- <w:tblHeader/> repeated automatically!
        [ Row 2: Complete row text preserved ]
        [ Row 3: Next data ]
```

## 3. Excel Formula Shift Corruption (`ERR_XLSX_003`)

When inserting a new row or 2D data block into an existing financial spreadsheet:
- If an AI writes raw cells, all downstream `=SUM(B5:B10)` formulas become invalid or fail to include the newly inserted rows.
- Directly setting cell `.value = 100` strips existing number formatting (`$#,##0.00`) and borders.

**Docwright's 2D Block Mutator**:
- Tokenizes cell formulas via **AST (Abstract Syntax Tree)**.
- Automatically adjusts row and column indices in dependent formulas.
- Automatically preserves DrawingML corporate logos and merged headers.

## 4. Scanned PDF Table Extraction Hallucinations

Extracting tables from scanned PDFs via standard OCR often scrambles multi-column layouts, merges unrelated cells, or fails on skewed scans.

Docwright uses **Document Vision Layout Measurer (`docx.measure_pdf_layout`)**:
- Uses **Hough transform** to calculate rotation angle $\theta$ and un-skew coordinates.
- Applies **OpenCV morphological kernels** to detect physical borders (`H_kernel` and `V_kernel`).
- Extracts clean column ratios (`[0.25, 0.45, 0.30]`) without coordinate guessing.
