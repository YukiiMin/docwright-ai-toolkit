## 1. Automatic Multi-Page Table Pagination Protection

When generating long tables in Word, two common layout issues occur if pagination properties are omitted:
- Tall cells split mid-sentence across the bottom of Page 1 and top of Page 2.
- Page 2 displays data rows without repeating the column headers.

Docwright's table builder automatically configures every table row with row-split prevention and repeating header rows, while locking full-width section banners (`keep_with_next`) to the first data row beneath them.

## 2. Three Primary Word Workflows

### Workflow A: Corporate Jinja2 Templates (`docx.normalize_template` + `docx.render_template`)

Word editors frequently split a single placeholder like `{{ client_name }}` across multiple internal XML `<w:r>` runs when a user edits text or runs spellcheck. Always run `docx.normalize_template` before rendering:

```python
from doctools.operations.docx import docx_normalize_template, docx_render_template, docx_validate

# 1. Consolidate split {{ ... }} tags into clean runs
docx_normalize_template(
    file_ref="templates/contract_template.docx",
    output_path="templates/contract_normalized.docx",
)

# 2. Populate template variables
docx_render_template(
    template_path="templates/contract_normalized.docx",
    output_path="output/client_contract.docx",
    context={
        "client_name": "Vanguard Logistics Corp",
        "effective_date": "2026-10-16",
        "line_items": [
            {"service": "Core Platform License", "amount": "$24,000"},
            {"service": "Dedicated Support", "amount": "$6,000"},
        ],
    },
)

# 3. Validate structural integrity
res = docx_validate(file_ref="output/client_contract.docx")
print("Validation passed:", res.success)
```

### Workflow B: Surgical Style-Preserving Patching (`docx.patch`)

When you need to update specific clauses, dates, or numbers in an existing `.docx` file that does not use Jinja placeholders, use `docx.patch`. Its run-splicing engine locates text even when split across multiple formatting runs and replaces the characters while preserving the exact font, size, bold/italic state, and color.

```bash
docwright docx.patch --json '{
  "file_ref": "output/client_contract.docx",
  "output_path": "output/client_contract_v2.docx",
  "patches": [
    {"target_text": "$24,000", "replacement_text": "$21,500"}
  ]
}'
```

### Workflow C: Scanned PDF to 1:1 Editable Word Form

For scanned questionnaires, government forms, or legacy PDFs:
1. **`docx.measure_pdf_layout`**: Uses OpenCV morphological line detection and skew correction to measure exact table column ratios and row heights, assigning each cell a deterministic ID (`c0_0`, `c0_1`, ...).
2. **`docx.populate_layout_text`**: Injects transcribed text into the measured `LayoutSpec` by `cell_id` (supporting both `row_span` and `col_span`).
3. **`docx.compile_layout_spec`**: Compiles the populated layout into a verified `.docx` document (`merge_continued_tables=False` for 1:1 print form parity, or `True` for compact continuous tables).
